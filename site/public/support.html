Support

Help

PushArmor is a free project. Most answers are on this page and on the how-to page. To report a bug, open a GitHub Issue.

To delete your account, use Delete account in the app, or the account deletion page.

Sign-in

Which email addresses work? Only email addresses with plain ASCII characters are supported.

The code email. Each code email ends with: "Nothing happens unless this code is entered within 15 minutes. If you did not request it, ignore this email."

No code arrived? Check spam. If your address bounced earlier, the mail provider may block it until we clear it. Google and Apple sign-in keep working. To ask us to clear the block, see Privacy requests in the privacy policy.

Hide My Email. If you signed in with Apple and chose Hide My Email, the app shows the address under Signed in as. Use that address on your other peers. Find it in iOS Settings > Apple ID > Sign in with Apple, or at appleid.apple.com > Hide My Email.

Pairing

A pairing stays open for 14 days. Each pairing shows how much time is left. Tap Pair on a peer, then compare the pairing fingerprint on both peers.

"A new peer wants to pair" means someone tried to pair with this device and the try failed or came from an unknown peer. Ignore it unless you started a pairing. If a Reply button appears, this device has already answered 10 tries in 24 hours; tap Reply only if you started that pairing.

"Name wants to pair again. Tap Cancel pairing on its row, then pair." means that this device still holds an earlier, unfinished pairing with that peer. On the device that shows the notice, tap Cancel pairing on that row, then pair again. Use Remove only to really remove a peer: that peer is removed from the account; it signs in again with a new identity and pairs again with each of your peers.

Messages

"Invalid message received" means a message arrived that was already seen or is too old. It is dropped. "Could not read" means a message failed to decrypt or verify.

Lock screen and watch

Android shows message text on the lock screen unless the system setting hides sensitive notification content; iPhone follows Settings > Notifications > Show Previews. To hide it always, turn off Show message content on lock screen in the app (per peer or for all).

On Android and iPhone, the Always hide content switch (for all peers or per peer) shows "New message from Name" with no content, even when the phone is unlocked; the content is only in the app. The Apple Watch shows notices while the iPhone is locked, so it follows the lock-screen choice; per-app watch mirroring is set in the Watch app.

Turn off Send messages to watch to keep Android notifications off paired wearables entirely.

Android

On Android, each peer has its own notification channel, so you can set sound and importance per peer in the system settings.

Android limits high-priority pushes for rarely opened apps. If messages come late, open the app now and then, and turn off battery Restricted mode and app hibernation.

iPhone

While the phone is offline Apple keeps only the newest message, and alerts must be on; use Send again from history.

Firefox

The Firefox add-on keeps its own push connection to Mozilla. As a fallback, and always on Firefox for Android, it uses a small service worker on pusharmor.com (under /fx/). At install the add-on opens a setup page that asks to allow notifications for pusharmor.com. That service worker receives encrypted messages, shows a short "New message" notice and hands the encrypted message to the add-on. It never sees your keys or any plaintext.

If the add-on shows "Firefox push needs one click", open the setup page again and allow notifications.

Firefox without Google Play services (Fennec, Mull, IronFox): This Firefox build cannot receive push (no Google Play services). Use the Chrome extension or another Firefox build.
