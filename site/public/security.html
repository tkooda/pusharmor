Security and threat model

Your devices don't need to trust our relay server. Messages are encrypted on your device, and can only ever be decrypted by your own paired devices. Each app and add-on checks everything the server sends, so the server cannot change a message or pose as one of your devices. Keys are made on each device, and the private keys used to decrypt and sign messages never leave it. Where the device supports it, they are kept in its hardware key storage (the Secure Enclave on iPhone, the Android Keystore on Android).

The push service and our relay server can show a notification with text of their choosing on every platform; verified content appears only after your device decrypts it.

The vendor sees the size of a message (padded to a few standard sizes), not its content.

How devices trust each other

Two devices trust each other only after you pair them by verifying that the 4-character pairing fingerprint is identical on both screens. Every message is signed by the sending device and checked by the receiving device; repeated or old messages are dropped. A message that fails this check is never shown; History lists it as "PushArmor received a message it could not read". Messages you read inside PushArmor passed this check. A notification is only a prompt: if one looks wrong, open PushArmor and read the message there.

Reporting a security problem

Report it privately with GitHub private vulnerability reporting. Please do not open a public issue for a security problem. The source code is public on GitHub.
